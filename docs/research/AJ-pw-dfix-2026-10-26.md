## 0. The mission and its answer in one line

The W1 window's P0 (AI-pw-w1-2026-10-25 §1: fmt 15 corrupts resident-path expert compute at model
scale, every fmt-15 leg dead mid-decode with *"the router (bf16, 256 experts top-6, bias) failed: gate
present, first index -1"*, every fmt-7 leg clean) was **not the packed form**. It was the tier's
**hybrid host-pool CPU path** reading fmt 15's packed scale bytes with the **f32-scale stride** — every
output row past the first read its scale bytes 4× too deep, off the end of the scale range. Fixed
(`host_scale_row`), gated (a model-geometry regression test that fails 32 768 non-finite values
pre-fix and is clean post-fix), institutionalised (`deepseek-v4-smoke`, the model-scale smoke gate),
and **fmt 15 is the default again** — the model-smoke passes at defaults, armed, and on the fmt-7
escape hatch, where the pre-fix tree failed the same legs deterministically.

## 2. The root cause, precisely

`host_pairs` (vk_tier.c) hands `host_rows` each output row's scale pointer:

```c
const float *rs = h->tg < 0 ? (o < I ? h->sg : h->su) + (size_t)oo * (D/gs …) : NULL;   /* gate/up */
const float *rs = h->td < 0 ? h->sd + (size_t)o * (I/gs …) : NULL;                      /* down   */
```

`VktHostExpert.sg/su/sd` are `const float *` — the pointer advances in **float** units. PW-D taught
the *decode* (`host_rows`/`dev_dequant`: `((const uint8_t *)rs)[g]`) the packed byte read but left
the *stride* f32: fmt 15's scales are **ue8m0 bytes, ng a row** (2048·128 = 262 144 B a matrix at the
model's shapes), so row `oo`'s bytes were read at byte `4·oo·ng` instead of `oo·ng`.

- Row 0 is always correct — a decode step's single-row hybrid pair passes — and at unit
  shapes the wrong read stays inside the host pool's mapped block (no crash; the bytes it
  reads instead are other tensors' — wildly wrong scales, non-finite rows: reproducible at
  H=192/F=128, §3), which is why only the *model's* shapes turned it into the window's
  dead-mid-decode P0 and the 1-expert pool's segfault.
- At the model's shapes the last gate/up row reads ≈1 047 000 bytes into a 262 144-byte scale range:
  arbitrary pool bytes as ue8m0 exponents — a byte ≥ 0xC0 is a scale ≥ 2^65, garbage bytes reach
  2^127 — the expert's row goes ±inf, the MoE sum non-finite, and **one layer below the router takes
  it as input and fails exactly as the window saw**. With a 1-expert host pool the read runs ~3×
  past the mapping: SIGSEGV (the crash leg above).

The failure was geometry/timing-dependent (which experts the host pool held when decode touched
them) because the hybrid path only takes host-pool residents outside the device's PCIe share —
14 experts at the model's RAM plan, occasionally 2–3 of a prompt step's pairs.

## 3. Why every gate stayed green (the two misses, both now closed)

1. **No unit geometry reaches the model's *failure* mode, and the oracle was NaN-blind.**
   The corruption itself reproduces at any shape (a scratch harness at H=192/F=128 with a
   host pool: 5 rows off, 960 non-finite values pre-fix) — but the standing gates never saw
   it: the old `v4_hybrid_case` *did* run fmt-15 hybrid pairs and its 27 hybrid rows were
   wrong (non-finite), yet it passed on two counts at once — `double r = rel(c, y, n);
   if (r > worst) worst = r;` with `r` NaN is **false**, so a non-finite row never raises
   `worst` (it printed `worst row 0.00e+00` while 27 of its 138 rows were not bit-identical
   — exactly the 27 hybrid pairs), and its bit-identity bar `same*2 > dev` only needs half
   the rows, which the 111 device-computed rows carried. The suite's `step()` helper always
   guarded this (`if (!(r <= worst))`, "a NaN counts as the worst"); the hybrid cases did
   not.

## 4. The fix

- **`host_scale_row`** (vk_tier.c): the one row's scale pointer with the byte stride for fmt 15 and
  the f32 stride for every other format — both `host_pairs` call sites (gate/up and down). fmt 7's
  bits are untouched by construction (the f32 branch is the old expression verbatim).
- **The same class, closed beside it:** `qmatmul_grp_gemv.comp`'s writer tail multiplied the reduced
  sum by `sc.v[o]` for every format but 4 and 7 — 44e7e981 added fmt 7 to that guard, PW-D added
  fmt 15's *group* decode but not the *tail* guard, so a fmt-15 row through the grouped GEMV (a
  coop-matrix device's decode route; this RDNA2 rig has none, which is why no rig test could see it)
  was multiplied by four packed scale bytes read as a float. `fmt != 15` added — one line, found by
  the same audit that found the stride (a consumer reading an f32-layout assumption).
- **`COLI_VK_TIER_FMT15` re-read as asked** (no process-lifetime cache): the hotfix's static cache
  made the lever invisible to a second `vkt_init` in one process — the tests need to arm it late.
- **fmt 15 is the default again** (`dev_fmt`/`convert`); `COLI_VK_TIER_FMT15=0` keeps the f32-scale
  fmt 7 — the escape hatch, byte-identical to the pre-PW-D standing. CUDA keeps fmt 7 (no packed
  form in cu_xb.cu), unchanged.

## 5. The regression test (the minimized repro, permanent)

`model_hybrid_case` (tests/test_vk_tier.c, "model geometry:"): one layer at **the model's geometry**
(hidden 4096, inter 2048, gs 32, 8 experts, top-6, `VKT_ACT_SWIGLU_V4`), the device's budget too
small for the layer (2 of 8) beside a host pool holding the rest, `COLI_VK_HYBRID_PCIE=0` so every
host-pool pair runs the hybrid CPU path, four decode-class steps, **every** tier-held row checked
finite element-wise and against the V4-rounding reference:

- pre-fix (only the stride bug present, the object built from HEAD's vk_tier.c):
  `18 rows, 8 off the reference, 32768 non-finite values` → **FAIL**
- fixed: `8 hybrid pairs: 18 rows, 0 off, 0 non-finite, worst 1.93e-03` → PASS.

The case also asserts hybrid pairs actually ran (`hy > 0`) — the P0's path — and prints the counts.
It runs inside `vk-tier-check`, so the standing gate now reaches the model's shapes for this class.

## 6. The model-smoke gate (institutional)

`make deepseek-v4-smoke` (c/Makefile → `tests/deepseek_v4_smoke.sh`): the W1 lesson ("any slice
that changes a tier/chain *default* owes one model-scale smoke leg before merge") made standing.
Design: the real checkpoint (`MODEL`, default the rig's path) on a ~100-token prompt for 16 tokens;
checks rc=0, a non-empty coherent `generated_text` (≥3 words), and the failure lines —
`chained block failed`, `device is lost`, `submit failed`, any nonzero `failed N` counter; copies the
rig's frozen `.coli_usage`/`.coli_mfu` snapshots in where they exist, before the run and back in
after it — the engine writes its own counts at exit (the bench arms' protocol — the warm start plans
by the same counts every run, and the shared model's history is left as found); **skips
cleanly** when the model, the Vulkan device or the VK build is absent; **fails** when `/dev/dri` has
other holders (an arm beside a co-tenant is confounded, not skipped). The tier's format lever rides
the caller's environment — the gate at defaults runs the tree's standing default, `COLI_VK_TIER_FMT15=1`
the packed form, `=0` the escape hatch: the P0's three legs.
