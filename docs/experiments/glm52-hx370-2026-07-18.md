# GLM-5.2 colibri int4 on AMD Ryzen AI HX 370 (Strix Halo) — CPU-only

Date: 2026-07-18. Machine: laptop with AMD Ryzen AI HX 370 (Strix Point/Halo),
Radeon 890M iGPU (igpu idles; colibri's CUDA/Metal backends do not target it),
96 GiB unified system RAM (shared as slower "VRAM" via UMA — not yet exercised
by colibri), Gen4 NVMe at ~7 GB/s read. OS: Linux. No discrete GPU.

Goal of this note: record the first successful end-to-end run of the
`mateogrgic/GLM-5.2-colibri-int4-with-int8-mtp` snapshot on this APU, and the
measured decode performance under a fixed RAM budget. This is the regime the
README's "SSD note" predicts — a 744B frontier MoE answering on a machine with
no GPU, streaming experts from NVMe on miss.

## Build

`cd c && make` (gcc 13.3.0, `-O3 -march=native -fopenmp`). Produces the `glm`
engine binary. All Python deps present: torch 2.12 cpu, safetensors 0.8, numpy
2.4.6, huggingface_hub 1.19, transformers 5.12.0 (matches the model's
`transformers_version`).

## Run discipline

Fixed `TEMP=0 TOPP=0 TOPK=1`, fixed 96-token greedy count, non-degenerate
"water cycle" prompt (the README's "sky is blue" prompt degenerates and gives
0% MTP acceptance — do not use it for speculation comparisons). Core pinning
per the 6x5090 lab's winning config: `OMP_NUM_THREADS=12
OMP_PROC_BIND=spread OMP_PLACES=cores`. `COLI_GPUS=none` (CPU-only; the 890M
iGPU is not used by colibri).

## Where the time goes (baseline pinned, ram=56, DRAFT=0)

- expert-disk wait: **89.4s of 125s decode (71%)** — the dominant cost.
- expert-matmul: 3.99s (CPU int4 kernel).
- attention: 24.2s (projection/RoPE 5.1s, score-softmax-value 9.9s, output
  projection 9.2s) — high because attention runs on CPU, no GPU offload.
- other: 7.9s.

## Findings

1. **The model runs end-to-end on the HX 370.** Load, prefill, decode, and the
   int8 MTP head all function. This is a real, working pipeline — not a stub.
2. **Performance is disk-bound, not compute-bound.** At ram=50→56, tok/s went
   0.76→0.77 (flat) while hit rate rose only 49.8%→53.2% and
   experts-loaded/token stayed 74.2. RAM is at diminishing returns: the extra
   6 GB bought 4 hit-points. We cannot fit the ~100 GB resident set the lab
   machine used (whole model in VRAM+RAM, zero disk) without exceeding 96 GB
   total — the system baseline already consumes ~29 GB, so colibri RSS of ~46
   GB puts us at the safe wall.
3. **Ceiling if disk were eliminated:** expert-matmul 4s + attention 24s +
   other 8s ≈ 36s/96tok ≈ **~2.7 tok/s theoretical max at 100% residency** on
   this CPU. Disk pulls the real number to ~0.77.
4. **Diminishing RAM returns mean the next lever is NOT more RAM** (capped by
   96 GB) but either (a) GPU matmul — the 890M iGPU is idle and colibri does
   not target it, or (b) a coalesced/streaming load path so the 7 GB/s SSD is
   actually saturated instead of doing random small expert reads.
5. **MTP speculation on this MoE-with-misses is neutral-to-negative, confirmed.**
   The MTP-on run measured **0% acceptance (0/24)** and **0.58 tok/s** — ~24%
   *slower* than DRAFT=0's 0.76. Mechanism: the S verify positions route to
   mostly different experts (experts/token rose 74.2 → 93.2), each a disk miss,
   and with 0% acceptance there is zero amortization. The int8 head's 39-59%
   acceptance only pays off when experts are resident (disk=0), which 96 GB of
   unified RAM cannot achieve for a ~100 GB resident set. **Verdict: keep
   DRAFT=0 on this box.** The 6x5090 doc's conclusion holds here verbatim.

## Output quality (the important result)

The earlier garbled output ("yes_m_ b in,-the", "autnetwork Answer") was NOT a
model or quantization defect — it was **greedy degeneration from TOPK=1
TEMP=0**. Two natural-sampling runs (TOPP=0.95, TEMP=1.0, ram=50, DRAFT=0)
produced fluent, correct prose:

- water-cycle prompt → "That is exactly right! The water cycle (also known as
  the hydrologic cycle) is a continuous, complex system. ... it's essentially
  powered by two massive natural forces: **the sun** and **gravity**. Here is
  a quick breakdown of how the major processes of the cycle..."
- The model follows the conversational framing, uses correct terminology, and
  stays on topic for the full 64 tokens.

**Quality verdict:** the colibri int4 snapshot is sound on the HX 370. The
only quality risks are (a) greedy sampling (use TOPP≈0.95, the model's own
`generation_config` default, not TOPK=1/TEMP=0) and (b) the ~47-52% expert
miss rate, which substitutes streamed-for-resident experts on ~half of steps
and adds noise. Raising residency (more RAM, or the iGPU tier below) improves
both speed and output stability.

## The iGPU is the real lever (CPU-only is a ceiling, not a baseline)

colibri's backends are CUDA (`backend_cuda.cu`) and Metal (`backend_metal.mm`)
only. The HX 370's Radeon 890M (RDNA 3.5) is **idle** — it does no inference.
Two consequences:

1. **Speed:** all expert matmul + attention runs on 12 CPU cores. Full residency
   would still cap near ~2.7 tok/s on CPU (attention alone is 24s/96tok). The
   iGPU's matmul throughput is the only path to multiples of that.
2. **Quality:** because the 890M shares the same 96 GB unified memory, an iGPU
   compute tier could pin the hot expert set in memory the GPU addresses,
   raising hit rate toward 100% *without needing more RAM* — killing the disk
   wait that drives both slowness and routing noise.

No ROCm/Vulkan/oneAPI backend exists in colibri today. Adding one (or a
`backend_hip.mm` / Vulkan compute path) is the single highest-value
engineering task for this machine. It is the only lever that moves both speed
and quality within the 96 GB wall.

## Comparing to the lab (6x RTX 5090, 2026-07-12)

| | 6x5090 (full resident) | HX 370 (this box) |
| --- | --- | --- |
| decode tok/s | 6.28-6.84 | ~0.77 |
| expert hit | 100% | ~53% |
| disk wait | 0s | ~71% of decode |
| VRAM+RAM | 176+191 GB | 46 GB (of 96 total) |
| compute | 6 GPU + 24 CPU | 12 CPU cores |

The gap is entirely the missing VRAM tier + GPU matmul + full residency. The
HX 370 result is ~9x the README's predicted 0.05-0.1 tok/s for a 1 GB/s dev
box, because this SSD does ~7 GB/s.
