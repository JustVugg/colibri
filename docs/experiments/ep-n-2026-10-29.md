# DeepSeek V4 (Flash): routed-expert parallelism across two CUDA devices

What is measured here: the engine's routed-expert (MoE) decode tier split
across a second CUDA device. With `DSV4_CUDA_EP_DEVICES="0,1"` the 256 routed
experts are divided into contiguous bands, one per device — each token's routed
experts compute on whichever device their band lives on, and the partial sums
are combined on the host. The dense/shared-expert path, KV cache and attention
stay on the primary device. The output must not change; the wall clock should
roughly halve on a two-GPU host, since routed experts were already the
dominant decode cost.

## Method

Single prompt, three runs per arm, arms interleaved after an engine restart per
arm so both begin from the same resident footprint:

```
Write the numbers 1 through 120, comma separated.   (prompt 16 tokens, temperature 0, max_tokens 800)
```

The prompt is small by design: it exercises decode only (the batched-prefill
union engages at ≥256 prompt tokens and is measured separately below), so the
two arms differ only in the routed-expert path. `DSV4_CUDA_EP_DEVICES` is the
only env variable that differs between the arms.

```
S=$(date +%s); curl -s -m 1500 -X POST http://colibri-deepseek-v4-flash:5000/v1/chat/completions \
  -H "Content-Type: application/json" -d @perf.req -o arm.json; E=$(date +%s); echo $((E-S))
```

## Results

**2.12× faster decode (wall clock), token-exact.** Every run of both arms
returns the byte-identical 358-token response (sha256
`0b810df860cc79589824d7b95382cf40b3dcc3a9f5bf9c3d0ee995bc08afa7af`), so the
band split does not perturb the output; the speedup comes entirely from
doubling the routed-expert compute surface. During the trial arm both cards sit
at ~13.0–13.1 GiB; during the baseline arm the second card holds only the
unrelated GLM Vulkan context (~0.7 GiB).

Prefill union (a separate path exercised with a 924-token prompt): with EP on,
the engine logs `v4_gpu moe-batch=on … moe-ep=on devices=2` and refills each
band's expert bank on its own device; with VRAM too tight for the extra bank
(e.g. after long runs have grown the decode mirrors) it logs
`moe-batch=off (bank allocation failed; CPU union stays)` and falls back to the
existing CPU path — correct output either way.

## Scope and caveats

- Verified N=2 on this box (the only hardware here). The code is written for N
  devices (contiguous bands of 256/N experts, N−1 peer banks + mirror caches);
  N>2 is compile-verified only.
- The engine keeps the band split internal: same API, same output, one env
  var. `DSV4_CUDA_EP2=1` (the original two-device spelling) remains accepted as
  an alias.
- tok_s here is completion tokens over the whole turn (prefill included),
  measured through the OpenAI-compatible endpoint rather than the harness's
  engine-direct `cap` runner; the token-exactness check serves as the validity
  gate in its place.
